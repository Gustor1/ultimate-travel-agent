Système : `ultimate-travel-agent` (Local-First, Privacy-First)

---

## 1. Objectif de l'Audit

Cet audit dresse l'inventaire complet des capacités d'intégration de données de voyage dans le système `ultimate-travel-agent`. Il applique une stricte rigueur d'ingénierie :
- **Transparence absolue** sur l'origine des données (aucune donnée mockée ne doit être maquillée en donnée live).
- **Zéro clé obligatoire** : le système fonctionne à 100% en local et hors-ligne sans clé API ni compte payant.
- **Zéro transaction financière** : interdiction totale d'achats, réservations automatisées ou débits bancaires.
- **Catégorisation explicite** des fournisseurs de données selon leur statut technique, juridique et contractuel.

## 3. Typologie Rigoureuse des Fournisseurs

### A. Fonctionnalités Réellement Connectées (Live)
- **Aucune** par défaut (architecture 100% locale déterministe).
- En mode live optionnel : architecture préparée pour des connecteurs directs conditionnés à la présence d'une clé API valide ou d'un endpoint local (ex: instance OSRM locale, API Open-Meteo sans clé).

### B. Fonctionnalités Actuellement Mockées (Offline / Mock)
1. **Recherche de vols** : Offres représentatives (AF, Vueling, Icelandair), cabine standard, liens vers portails officiels de billetterie.
2. **Recherche de trains** : Liaisons TGV / Renfe / ICE, correspondances, durées porte-à-porte, liens vers SNCF Connect / Renfe.
3. **Recherche d'hébergements** : Hôtels de charme et résidences dans quartiers calmes (Gràcia, Hlíðar), prix estimatifs, zéro inventaire en direct.
4. **Avis d'hôtels & réputation** : Scores agrégés (4.3 - 4.7/5) et extraits synthétiques.
5. **Activités et excursions** : POI majeurs avec horaires standards, tarifs d'entrée, créneaux conseillés, plans B météo et fermeture.
6. **Cartes, distances et itinéraires** : Matrices de distances kilométriques, durées de route moyennes, ordonnancement géographique des étapes.
7. **Météo** : Profils climatiques saisonniers historiques par ville (Barcelone, Reykjavík, etc.).
8. **Taux de change** : Table locale de parités (EUR, USD, GBP, JPY, ISK, CHF, NOK, CAD) avec marge de sécurité bancaire (+5%).
9. **Guides et contexte local** : Renseignements culturels, étiquette, transports en commun.
10. **Découverte sociale** : Recommandations tendances (gastronomie, spots photo) marquées strictement `social_discovery_only`.

## 4. Analyse Détailée des Fournisseurs Candidats

### 1. Vols (Flights)
- **Amadeus Self-Service APIs (Flight Offers Search)** :
  - *Statut* : Fournisseur candidat préparé.
  - *Type* : Nécessite une clé API (`AMADEUS_CLIENT_ID`, `AMADEUS_CLIENT_SECRET`).
  - *Coût* : Tier gratuit sandbox (2 000 requêtes/mois en test), pay-as-you-go en production.
  - *Règle* : Recherche en lecture seule. Pas de réservation de PNR ni d'émission de billet (pas d'API Flight Create Orders).
- **Aviation Edge / AviationStack** :
  - *Statut* : Fournisseur candidat préparé.
  - *Type* : Nécessite une clé API (`AVIATION_EDGE_API_KEY`).
  - *Coût* : Freemium limité. Utile pour les horaires réels et statuts de vol.
- **Google Flights** :
  - *Statut* : **Fournisseur refusé / Inéligible**.
  - *Motif* : Google Flights ne dispose d'aucune API publique officielle ouverte aux développeurs tiers. Tout scraping de l'interface Google Flights viole les conditions d'utilisation de Google. Le système fournit uniquement un lien vers le portail officiel de la compagnie ou de recherche.

### 2. Trains (Rail & Ground Transit)
- **SNCF Connect / SNCF Réseau API** :
  - *Statut* : Fournisseur candidat préparé.
  - *Type* : Nécessite un compte développeur SNCF et token d'authentification.
  - *Conditions* : Couvre le réseau ferroviaire français. Liens officiels vers `sncf-connect.com`.
- **DB Hafas (Deutsche Bahn)** :
  - *Statut* : Fournisseur candidat préparé.
  - *Type* : API publique ou wrapper open-source. Vérification de licence nécessaire pour usage de production.
- **Navitia (Kisio Digital)** :
  - *Statut* : Fournisseur candidat préparé.
  - *Type* : Nécessite un token API (`NAVITIA_API_KEY`). Tier gratuit disponible pour l'intermodalité en Europe.
- **GTFS / GTFS-Realtime (Transports Ouverts)** :
  - *Statut* : Compatible mode hors ligne et données ouvertes (Open Data sous licence ODbL).

### 3. Hébergements et Avis (Accommodation & Reviews)
- **Amadeus Hotel Search API** :
  - *Statut* : Fournisseur candidat préparé.
  - *Type* : Nécessite `AMADEUS_CLIENT_ID` / `AMADEUS_CLIENT_SECRET`.
  - *Usage* : Recherche de listes d'hôtels et fourchettes de prix indicatives. Aucune réservation (`Hotel Booking API` exclue).
- **StayAPI (Trip.com Reviews)** :
  - *Statut* : Fournisseur candidat préparé pour **les avis uniquement**.
  - *Type* : Nécessite une clé API (`STAYAPI_API_KEY`).
  - *Règle stricte* : Ne fournit pas de disponibilité temps réel ni d'inventaire complet de réservation. Utilisé exclusivement pour consolider les notes et commentaires clients.
- **Trip.com Partner API** :
  - *Statut* : Nécessite un partenariat formel entreprise (B2B Affiliate). Non activable sans contrat commercial.
- **Booking.com Demand API** :
  - *Statut* : **Nécessite un partenariat commercial**. L'API Booking Affiliate Partner est fermée aux développeurs indépendants sans volume d'affaires prouvé. Refus d'activation sans agrément.
- **Hotelbeds APItude** :
  - *Statut* : Nécessite un compte d'agence de voyage et vérification commerciale B2B. Préparé en architecture, non activé.

### 4. Activités et Excursions (Activities)
- **GetYourGuide Partner API** :
  - *Statut* : Nécessite un agrément partenaire affiliate (`GETYOURGUIDE_API_KEY`).
  - *Usage* : Recherche de catalogues et de prix indicatifs. Zéro panier ni paiement.
- **Viator Partner API (Tripadvisor)** :
  - *Statut* : Nécessite un compte Viator Travel Agent / Partner (`VIATOR_API_KEY`).
  - *Usage* : Consultation d'activités, durées et restrictions d'accès.
- **OpenTripMap API** :
  - *Statut* : Fournisseur ouvert avec clé gratuite (`OPENTRIPMAP_API_KEY`).
  - *Licence* : Données sous licences libres (ODbL, CC BY-SA).
- **Bureaux de tourisme et billetteries officielles** :
  - *Statut* : Compatible mode hors ligne. Liens officiels directs vérifiés.

### 5. Cartes, Distances et Itinéraires (Maps & Routing)
- **OSRM (Open Source Routing Machine)** :
  - *Statut* : **100% compatible hors ligne**.
  - *Type* : Peut s'exécuter en local via conteneur Docker ou binaire sans aucune clé API.
- **OpenRouteService (ORS)** :
  - *Statut* : Fournisseur candidat préparé.
  - *Type* : Nécessite une clé gratuite (`ORS_API_KEY`). Quota généreux pour profils piéton, cycliste et automobile.
- **Nominatim (OpenStreetMap Geocoding)** :
  - *Statut* : Open source, sans clé obligatoire.
  - *Contrainte* : Respect strict de la politique d'utilisation (max 1 requête par seconde, `User-Agent` obligatoire).
- **Google Maps Platform (Routes API)** :
  - *Statut* : Nécessite une clé API (`GOOGLE_MAPS_API_KEY`) et une carte bancaire pour l'activation du compte Google Cloud (même sous le crédit gratuit mensuel de 200 $).
  - *Recommandation* : Laisser désactivé au profit d'OSRM et OpenRouteService pour préserver la gratuité et la vie privée.

### 6. Météo (Weather)
- **Open-Meteo** :
  - *Statut* : **Recommandé en priorité**.
  - *Type* : Open-source, **sans clé API requise**, gratuit pour usage non-commercial.
  - *Capacités* : Prévisions à 7-14 jours, archives météo historiques, détection de pluie/vent pour déclenchement des plans B.
- **OpenWeatherMap** :
  - *Statut* : Fournisseur alternatif préparé.
  - *Type* : Nécessite une clé API (`OPENWEATHER_API_KEY`). Tier One Call 3.0 avec quota quotidien.

### 7. Devises (Currency)
- **Banque Centrale Européenne (BCE / ECB)** :
  - *Statut* : **Recommandé en priorité**.
  - *Type* : Flux officiel public, gratuit, sans clé API.
  - *Capacités* : Taux de référence officiels journaliers de l'Euro face aux devises majeures.
- **Table Locale Déterministe** :
  - *Statut* : **100% compatible hors ligne**. Zéro dépendance réseau.

### 8. Avis et Contenu Local (Reviews & Guides)
- **TripAdvisor Content API** :
  - *Statut* : Nécessite une clé API officielle (`TRIPADVISOR_API_KEY`).
  - *Règle* : Conforme à la version actuelle de l'API TripAdvisor (v2/partner). Aucune dépendance sur d'anciennes API dépréciées.
- **Wikivoyage / Wikimedia API** :
  - *Statut* : Open data sous licence CC BY-SA 4.0, sans clé API, 100% légal et consultable hors-ligne via caches locaux.

### 9. Découverte Sociale (Social Discovery)
- **Module Expérimental Découverte Sociale** :
  - *Réseaux* : RedNote (Xiaohongshu), Douyin, TikTok, blogs locaux.
  - *Statut légal & technique* : **Interdiction de scraping automatisé agressif**. Utilisation exclusive d'exports autorisés, flux RSS ou APIs de recherche publiques.
  - *Règle de confiance* : Tout résultat issu de ce canal est obligatoirement étiqueté `social_discovery_only` et `price_status: needs_verification`. Il ne peut jamais être présenté comme une information certifiée.

## 6. Conclusions et Directives de Développement

1. **Architecture Provider Hub** :
   - Tous les connecteurs ci-dessus doivent s'articuler autour d'une interface commune `Provider` avec détection automatique de la configuration.
   - Si aucune clé n'est fournie, le connecteur opère en mode `offline` ou `mock` sans lever d'exception bloquante pour l'utilisateur.
   - En mode `live`, si la clé est absente, une exception typée `ProviderConfigurationError` est levée avec message explicite sur les variables manquantes.
2. **Sanctuarisation Zéro Achat** :
   - Aucune méthode `book()`, `reserve()`, `pay()` ou `create_order()` n'est créée.
   - Tout lien vers une plateforme tierce est étiqueté `official_booking_url` et requiert une démarche manuelle et externe de l'utilisateur.
3. **Traçabilité des Niveaux de Vérification** :
   - Tout résultat normalisé porte son mode (`offline`, `mock`, `live`), son horodatage de récupération (`retrieved_at`), son statut de prix (`confirmed`, `estimated`, `needs_verification`), son statut de disponibilité et son niveau de preuve.
